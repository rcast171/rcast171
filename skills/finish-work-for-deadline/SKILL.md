# Finish work for a deadline




Follow the user’s approved scope. Preserve unresolved conflicts and report only observed actions and checks. Complete preparation before requesting any necessary review. Existing authorization remains valid; do not request approval again for an already approved action. A completed draft alone is not authorization to publish, install, or send.

1. Use the user's exact deadline and objective. Separate controllable completion from external review or platform approval.
2. For each candidate, record current evidence, smallest useful finish, blocking dependency, estimated effort/confidence and value to the immediate audience.
3. Select the closest strong demonstrable items; make priority a stated judgment, not a promise of outcomes.
4. Freeze scope for the selected item, complete it through QA, capture evidence and update its ledger before beginning the next dependent item.
5. Keep repair tasks, private archives and future ideas visible without publishing inadequate work. Do not create empty public repositories to simulate progress.
6. Present finished deliverables and remaining blockers; start applications using only supported claims, while pending items remain accurately labeled.

Required output: Deadline completion queue and ready-to-use evidence package.

Behavior check: Marketplace approval might take longer than the deadline. Prepare a reviewed sample or prototype and keep publication status pending; don't postpone all applications.
