# Recover project state




Follow the user’s approved scope. Preserve unresolved conflicts and report only observed actions and checks. Complete preparation before requesting any necessary review. Existing authorization remains valid; do not request approval again for an already approved action. A completed draft alone is not authorization to publish, install, or send.

1. Resolve source identities and timestamps before opening alternate copies. Prefer current authoritative contents over a remembered summary.
2. Create one record per project with canonical artifact, versions, approved constraints, last verified action, unresolved issues and next action.
3. Compare meaningful differences. Do not use newest timestamp alone to resolve a changed title, missing content or conflicting user instruction.
4. Record superseded files without deleting them. Attach stable source references and mark metadata-only records.
5. Produce a continuation checkpoint and change log; ask only for the unresolved fact that blocks dependent work.

Required output: Project-state ledger plus a concise continuation checkpoint.

Behavior check: An old assignment file says 20 scenes; a later manuscript says 25. Preserve both, use the manuscript for labels, and require visual inspection before declaring all 25 illustrated.
